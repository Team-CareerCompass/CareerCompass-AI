# 프롬프트 버전 기록

**파일명이 버전이다.** `parse_posting.v3.md` 를 고치지 않는다 — `v4.md` 를 새로 만들고 평가셋을 돌리고 여기에 적는다. 그래야 「지난주보다 나빠졌다」를 커밋 로그로 답할 수 있다 (#3).

쓰는 버전은 **가장 높은 번호가 아니라 `CC_PARSE_PROMPT_VERSION` · `CC_DRAFT_PROMPT_VERSION` 이 가리키는 것**이다. 평가로 고른다 (초안은 지금 최신 = v2).

```
python scripts/evaluate.py --pipeline llm --save       # 지금 설정으로
CC_PARSE_PROMPT_VERSION=v2 CC_HCX_MODEL=HCX-005 ...    # 버전·모델 바꿔서
```

### 배운 것

- **DASH-002 는 프롬프트로 더 못 올린다.** 다섯 버전이 재현율 45~60%, 정밀도 52~71% 안에서 서로 자리만 바꿨다. 한쪽을 올리면 다른 쪽이 내려간다.
- **예시(few-shot)는 작은 모델에 독이다.** `preferences: []` 예시를 주면 우대를 안 내고(v3), 우대가 든 예시를 주면 우대가 없는 장학금에도 3~5개씩 낸다(v4). 예시의 모양을 베낀다.
- **「전체에서 고른다」「5~10개」는 잡음을 부른다.** 두산(직무 44개)이 전부 나열해 스키마 상한에 걸렸고, 「2026 하반기」「제6회」가 키워드로 들어왔다. → 게이트웨이가 목록 길이를 실패가 아니라 절단으로 바꿨다.
- **긴 금지 목록은 안 듣는다.** 「활동비·수료증은 우대가 아니다」를 세 버전에 적었는데 008 은 매번 냈다.
- **모델을 올려도 v1 로는 나아지지 않는다.** HCX-005 + v1 이 DASH-002 + v1 보다 못하다. 005 는 v2 의 구조화된 지시를 더 잘 따라 우대에서만 이긴다(57/73). 5배 비용.
- `formQuestions: null` 을 스키마 위반으로 처리하던 것도 v5 실측에서 잡았다 — `null` 은 빈 배열이다.

### 지금 선택 — v1 + DASH-002

키워드 정밀도가 가장 높고(71%) 제일 싸다. BE 의 분야 유사도가 키워드↔관심분야 부분 일치라, 잡음 키워드는 점수를 흐린다 — 정밀도가 재현율보다 중요하다. 우대는 v2+005 가 낫지만(F1 .64 vs .55) 우대 20% 축 하나 때문에 5배를 낼 이유는 아직 없다.

**다음에 해볼 것**: 31건에서도 v1 이다. 키워드 재현율 50% 선이 DASH-002 의 천장으로 보인다 — 올리려면 모델(005 + v2 계열)이지 프롬프트가 아니다. 우대 20% 축 하나에 5배 비용을 낼지는 팀 판단.

### 무엇을 바꿨나

- **v2 프롬프트**: 회사명·기술명은 입력에 있는 것만(한글 표기도 같다) · `keywords` 는 지원자가 한 것이 아니다 · 글자 수 범위를 **채운다** · 어미를 **모든 문장**에
- **게이트웨이** (`TONE_RULES`·`ending_ratio`): casual 지시에 어미 예시와 금지(「~합니다」 한 문장도 안 됨). **어미 비율을 실측해 80% 미만이면 1회 재요청** — 글자 수 상한과 같은 패턴. 이게 톤을 살렸다(1/14 → 13/14)
- **길이 하한** (`FILL_MIN` 2/3): 프롬프트에 「N자 이상」 → 효과 0 (48%→48%). 미달 시 재요청 → 효과 0, 비용 1.5배 → **뺐다**. 문장 수(「문장 N개 이상, 경험마다 상황·행동·결과」)로 바꾸니 소표본에서 48→54% → 이것만 남김
- **경험 0개**: 모델을 안 부르고 안전 초안(`fallback: true`). v2 실측에서 모델이 「컴퓨터공학 전공」「환경 보호 연구」「[지원자 이름]」을 만들었다 — 근거가 0 이면 검증할 것도 0

### 배운 것

- **톤은 프롬프트로 안 되고 실측 재요청으로 된다.** 「~해요체」라고 적으면 14건 중 2건, 어미 예시·금지를 적고 어미 비율로 재요청하면 13건. 재요청은 casual 에서만 돌아 건당 +0.12원.
- **길이는 DASH-002 의 천장이다.** 어떻게 말해도 250~350자를 낸다. HCX-005 는 채우지만 **지어내서 채운다** — 007 「휠체어를 쓰는 친구를 위해 대체 텍스트 추가」, 011 「커밋 메시지 자동 생성」. 한국어 일화라 문자열 검증에 안 걸린다. 게다가 8건 중 2건 JSON 형식 실패. 짧은 정직한 답 > 긴 거짓 답.
- **한국어 날조는 문자열 검증 밖이다** — v1 「엔씨소프트에 입사한다면」(입력에 없는 회사), 「타입스크립트」(TypeScript 의 한글 표기로 영문 대조 우회), v2 「웹 접근성을 고려한 디자인 요소 추가」(키워드를 경험처럼). `forbidden` 목록이 사후에 잡는다. 규칙으로 못 잡는 것은 #29 에 남긴다.
- **재생성은 온도 0.7 만으로 다른 글이 나온다** — 3-gram 0.30 (다른 항목끼리 0.03), 문장 복사 0. `previousAnswer` 없이도 #19 완료 조건은 만족. 1/13 은 0.5 넘음(001 — 경험 3개를 같은 순서로 나열).
- **톤을 바꾸면 인용하는 사실이 조금 달라진다** — Jaccard 0.86. 모순은 아니고 선택 차이(한쪽만 「30분」을 씀). 둘 다 사실검증은 통과.
