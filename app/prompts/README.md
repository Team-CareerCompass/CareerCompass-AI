**005 두 줄은 09-16 에 추가.** v2 + HCX-005 가 **모든 지표에서 v1 + DASH-002 를 이긴다** — 키워드 +8/+6%p, 금지어 3→1, 우대 +18/+8%p. 대가는 공고당 0.4 → 2.8원(6배), 월 5,000건이면 2,000 → 14,000원. 13건 때의 「005 는 우대만 낫다」는 표본이 작아서였다. `CC_PARSE_PROMPT_VERSION=v2 CC_HCX_MODEL_PARSE=HCX-005` 로 켠다. **기본은 아직 v1 + DASH-002** — 바꾸는 것은 팀 판단(월 1.2만원 차이, 인프라보다 싸다). 기록 `eval/2026-09-16T102{144,247}Z_llm-v{2,1}-HCX-005.json`.

### 배운 것

- **DASH-002 는 프롬프트로 더 못 올린다.** 다섯 버전이 재현율 45~60%, 정밀도 52~71% 안에서 서로 자리만 바꿨다. 한쪽을 올리면 다른 쪽이 내려간다.
- **예시(few-shot)는 작은 모델에 독이다.** `preferences: []` 예시를 주면 우대를 안 내고(v3), 우대가 든 예시를 주면 우대가 없는 장학금에도 3~5개씩 낸다(v4). 예시의 모양을 베낀다.
- **「전체에서 고른다」「5~10개」는 잡음을 부른다.** 두산(직무 44개)이 전부 나열해 스키마 상한에 걸렸고, 「2026 하반기」「제6회」가 키워드로 들어왔다. → 게이트웨이가 목록 길이를 실패가 아니라 절단으로 바꿨다.
- **긴 금지 목록은 안 듣는다.** 「활동비·수료증은 우대가 아니다」를 세 버전에 적었는데 008 은 매번 냈다.
- **모델을 올려도 v1 로는 나아지지 않는다.** HCX-005 + v1 이 DASH-002 + v1 보다 못하다. 005 는 v2 의 구조화된 지시를 더 잘 따라 우대에서만 이긴다(57/73). 5배 비용.
- `formQuestions: null` 을 스키마 위반으로 처리하던 것도 v5 실측에서 잡았다 — `null` 은 빈 배열이다.

### 지금 선택 — v1 + DASH-002

키워드 정밀도가 가장 높고(71%) 제일 싸다. BE 의 분야 유사도가 키워드↔관심분야 부분 일치라, 잡음 키워드는 점수를 흐린다 — 정밀도가 재현율보다 중요하다. 우대는 v2+005 가 낫지만(F1 .64 vs .55) 우대 20% 축 하나 때문에 5배를 낼 이유는 아직 없다.

### 무엇을 바꿨나

- **v2 프롬프트**: 회사명·기술명은 입력에 있는 것만(한글 표기도 같다) · `keywords` 는 지원자가 한 것이 아니다 · 글자 수 범위를 **채운다** · 어미를 **모든 문장**에

- **길이 하한** (`FILL_MIN` 2/3): 프롬프트에 「N자 이상」 → 효과 0 (48%→48%). 미달 시 재요청 → 효과 0, 비용 1.5배 → **뺐다**. 문장 수(「문장 N개 이상, 경험마다 상황·행동·결과」)로 바꾸니 소표본에서 48→54% → 이것만 남김

- **길이는 DASH-002 의 천장이다.** 어떻게 말해도 250~350자를 낸다. HCX-005 는 채우지만 **지어내서 채운다** — 007 「휠체어를 쓰는 친구를 위해 대체 텍스트 추가」, 011 「커밋 메시지 자동 생성」. 한국어 일화라 문자열 검증에 안 걸린다. 게다가 8건 중 2건 JSON 형식 실패. 짧은 정직한 답 > 긴 거짓 답.
- **한국어 날조는 문자열 검증 밖이다** — v1 「엔씨소프트에 입사한다면」(입력에 없는 회사), 「타입스크립트」(TypeScript 의 한글 표기로 영문 대조 우회), v2 「웹 접근성을 고려한 디자인 요소 추가」(키워드를 경험처럼). `forbidden` 목록이 사후에 잡는다. 규칙으로 못 잡는 것은 #29 에 남긴다.
- **강조 카드는 순서를 따라간다 — 질문과 맞을 때만** (09-21, 5건). 카드 1↔2 를 바꿔 다시 돌리면 4건에서 새 첫 카드가 답의 앞에 왔다. 못 따라간 하나(001)는 **둘째 카드가 질문과 안 맞는 경우**였다 — 「지원 동기와 입사 후 포부」에 「알고리즘 스터디 운영」을 앞세우라고 해도 모델은 백엔드 경험으로 돌아갔다. 순서보다 질문 적합도가 이긴다. 프롬프트가 「앞의 것을 우선 쓰되, 질문과 맞는 것을 고른다」라고 적어 둔 그대로라 고치지 않았다

### 첫 실측이 09-14 사례를 그대로 재현했다

근거는 「RDB 1년 이상」 하나였는데 답은 **「데이터베이스 관련 자격증이 없으므로 RDBMS(예: MySQL)를 1년 이상 다뤄본 경험이 필요합니다」** 였다. 셋이 한 문장에 있다 — 없는 **자격증**(한국어 날조), 없는 **RDBMS·MySQL**(예시로 든 기술명), 그리고 「자격증을 따라」는 근거가 말하지 않은 해결책.

### 고친 것 셋 — 프롬프트가 막고, 가드가 받친다

1. **문장 단위 가드** (`_keep_cited_sentences`) — 항목 단위면 앞 문장이 근거를 지목한 덕에 뒷 문장의 빈말이 통과한다. 실제로 009 에서 「관련 자격증 취득이나 교육 이수를 고려할 수 있습니다」가 그렇게 살아남았다
2. **코멘트에도 사실검증** — 초안에만 있던 `fact_check` 를 걸고, 걸린 문장을 제거한다. **재요청은 하지 않는다** — 코멘트는 `null` 이 허용되고 점수는 그대로 나간다
3. **단정 방어** (`_overclaims_capability`) — 근거가 「설계」처럼 낱말 하나인데 「설계 능력이 있습니다」라고 쓰면 항목째 버린다. BE 과대매칭(HANDOFF §5)이 그대로 문장이 되는 것을 막는다

### 배운 것

- **가드만으로는 코멘트를 잃는다.** v1 프롬프트 + 새 가드는 날조를 0 으로 만들었지만 001 의 약점이 통째로 사라졌다(11/12). v2 프롬프트가 애초에 그런 문장을 안 쓰게 하니 둘 다 얻었다. 순서가 중요하다 — **프롬프트로 막고 가드로 받친다**
- **「예시로 들지 마라」를 적어야 한다.** 「근거에 없는 것을 쓰지 마라」만으로는 「RDBMS(예: MySQL)」가 나온다. 모델은 예시를 설명이라고 생각한다
- **과대매칭은 프롬프트로 안 막힌다.** v2 에 「흔한 낱말로 역량을 단정하지 마라」를 적었는데도 「설계 능력이 있습니다」가 나왔다. 규칙이 필요했다
- 침묵 9% 는 005 하나 — 근거가 과대매칭뿐이라 **침묵이 맞는 답**이다
