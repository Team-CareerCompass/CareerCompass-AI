# 분야 유사도 정답셋 (보고서 4.4.4)

적합도의 **분야 유사도 축(가중치 40%)** 을 두 방식으로 재기 위한 정답이다.

- BE 지금 구현: 공고 키워드와 관심 분야 글자의 부분일치 (`SuitabilityCalculator.fieldSimilarity`, BE #51)
- 보고서 설계: 임베딩 코사인 유사도 (Titan → 여기서는 HCX 임베딩 v2)

러너는 `scripts/compare_field_similarity.py`, 결과는 `docs/EVAL.md` 「분야 유사도」.

## 프로필 — BE 가 만드는 입력 그대로

BE `AnalysisService.interestTexts` 는 관심 직무마다 **코드와 라벨**을 넣고 그 뒤에 **태그**를 붙인다.
직무 코드·라벨은 BE `V2__meta.sql` 의 `job_category` 20개 그대로다(`jobLabels`).

```
backend 프로필 → ["backend", "백엔드 개발", "Java", "Spring", "서버"]
```

태그는 사용자가 자유롭게 적는 칸이라 분야마다 흔한 것 2~3개를 골랐다. 태그 없이(코드·라벨만)도
따로 잰다 — 온보딩에서 직무만 고르고 태그를 비우는 사용자다.

직무 20개 중 12개만 쓴다. 나머지(프론트엔드·모바일·DevOps·게임·QA·PM·영업·인사)는 이 공고 35건에
관련 공고가 거의 없어서 지표가 의미를 잃는다.

## 등급

| 등급 | 뜻 | 예 |
| --- | --- | --- |
| 2 | 그 분야가 공고의 **핵심 직무·활동** | 공공데이터 분석 경진대회(037) ↔ 데이터 |
| 1 | 공고의 **일부** 직무·활동이 그 분야 | 현대차 R&D(004)의 「모빌리티 UX」 ↔ 디자인 |
| 0 | 무관 (파일에 안 적는다) | |

- 장학금·학사 공지(001 002 003 019 020 021 023)는 직무 분야가 없다 — 전부 0
- **우대 사항만 겹치는 것은 0** — 서포터즈의 「사진/영상/디자인 툴」 우대는 디자인 직무가 아니다
- 여러 직무를 한 번에 뽑는 대기업 공고(004 009)는 실제로 있는 직무만 센다

지표는 **1 이상을 관련**으로 본다(기본). 2 만 관련으로 보는 엄격 기준도 같이 낸다.
