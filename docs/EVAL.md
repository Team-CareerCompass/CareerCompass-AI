# 무엇이 얼마나 나아졌나 (#5 #7)

같은 픽스처(공고 32건), 같은 채점기로 **세 파이프라인**을 나란히 돌린 결과다. 러너는 `scripts/evaluate.py --pipeline {baseline,rules,llm}`.

| 파이프라인 | 무엇 |
| --- | --- |
| `baseline` | **BE `HeuristicLlmGateway` 이식본** (`app/baseline.py`). AI 서버가 없을 때 BE 가 실제로 돌리는 구현이고, 그 클래스 주석이 「품질은 LLM 구현(CareerCompass-AI)이 대체하는 것을 전제로 한 기준선」이라고 적어 뒀다. **이것이 비교 대상이다** |
| `rules` | 우리 규칙만 (`app/rules.py` + 전처리). LLM 호출 0 |
| `llm` | 게이트웨이 전체 — 규칙 + LLM(v1 · HCX-DASH-002) 병합 |

±는 95% 신뢰구간이다. **표본이 42건이라 5%p 안쪽 차이는 아직 잡음**이다 — 키워드 재현율의 55% vs 52% 는 「같다」고 읽어야 한다.

**날조는 세 파이프라인 모두 마감일 0.** 기준선의 마감일 오답 14건은 날조가 아니라 「범위의 시작일을 집었다」류다.

## 읽는 법 — 어디서 이겼고 어디서 안 이겼나

**크게 이긴 것 — 규칙이 한다.**
- **마감일 33% → 100%.** 기준선은 본문의 *마지막* 완전 날짜를 집는다. 결과 발표일·운영 일정이 뒤에 있으면 그걸 마감일로 낸다. 우리 규칙은 범위의 끝을 잡고, 등록일 메타줄을 거르고, +18개월 상한을 둔다
- **공고 판별 89% → 100%.** 기준선에는 「공고가 아님」 개념이 없다 — 키워드 3개만 넘으면 학사공지도 공고로 본다(4건 오인). 그 4건은 사용자 목록에 그대로 올라간다
- **유형 85% → 100%.** 기준선의 `STOPWORDS` 에 「채용·장학금·공모전·대외활동」이 들어 있어 **유형 단서를 스스로 지운다**

**이긴 것 — 잡음을 줄였다.**
- 키워드 **재현율은 55% vs 52% 로 같다**(신뢰구간 ±7%p 안에서 겹친다). 이긴 것은 **정밀도 41% → 68%** 와 **금지어 21 → 5**. 기준선은 「2회 이상 등장한 단어」라 「모집·지원·2026·상세내용」 같은 것이 상위에 온다. BE 의 분야 유사도(적합도 40% 축)가 키워드 부분일치라 **잡음 키워드는 점수를 직접 흐린다**
- 우대 19% → 53%(재현) · 40% → 81%(정밀). 기준선은 「우대」가 든 줄을 전부 담아 혜택·안내문이 섞인다

**나중에 이긴 것 — 라벨을 붙이고 나서 (09-28).**
- **자격 조건 89% → 100%(날조 0).** 09-27 에 라벨을 붙였을 때는 셋 다 88% 로 같았다 — 우리 규칙이 BE 휴리스틱과 사실상 같은 정규식이었기 때문이다. 라벨이 실패 목록을 주자 고칠 수 있었다:
  - **본문 전체에서 첫 일치를 집던 것**을 「자격을 말하는 줄」 안으로 좁혔다. 날조 3건이 전부 범위 밖이었다 — 「추천인원 5명(자연.이공계열 80%)」(인원 배분) · 「10. 영상의학과 5급 의료기사」(모집 부서) · 「우대: … 환경관련학과」(우대)
  - 「전공 무관」·「전공·학점·성별·연령 제한 없음」은 **조건 없음**으로 읽는다. 1차 시도에서 이걸 빼먹어 「무관, 고졸 이상 학사학위 소지자…」를 전공 조건이라고 냈고 **날조가 3 → 5로 늘었다**
  - **절을 닫는 것과 줄을 건너뛰는 것을 갈랐다.** 문장 속 「2차 전형(면접 시)」이 자격 절을 통째로 닫아 017 의 전공 줄까지 못 갔다. 이제 헤딩 줄일 때만 닫는다
  - 「취업**지원대상**자」가 헤딩으로 오인돼 우대 절이 자격 절로 다시 열리던 것(040) — 기호 불릿 줄은 헤딩이 될 수 없다
  - 「2027**학년도**」의 7, 「2026 년도 1 학기 재학」의 1학기를 학년으로 집던 것. 학년을 먼저 찾고 없을 때만 학기를 본다
  - 「4.5만점 기준 3.5학점 이상」은 정규식 교대로 못 잡는다 — 교대는 **더 좋은 쪽이 아니라 더 앞쪽**을 고르므로 「12학점이상 이수 및 성적 4.5만점」이 먼저 걸렸다. 패턴을 순서대로 따로 시도한다

  **이 100% 는 42건에 맞춰 고친 결과다.** 같은 픽스처로 규칙을 고치고 같은 픽스처로 쟀으니 다음 공고에서는 떨어진다고 봐야 한다. 방어선은 `tests/test_rules.py` 의 회귀 테스트 8개 — 실패 사례를 픽스처 원문 그대로 박아 뒀다. 픽스처가 50건을 넘으면 다시 잰다.

  정답이 한 표현만은 아닐 때를 위해 라벨에 **목록**을 허용했다 — 019 는 같은 조건을 「3학년」과 「5학기 진학예정자」로 두 번 적는다. 정답을 하나로 고정하면 규칙이 아니라 **채점기가 틀린 것**이 된다.

**아직 안 이긴 것.**
- 키워드 재현율 50% 선은 DASH-002 의 천장이다. 올리려면 모델이다 — v2 + HCX-005 는 59%/72%, 우대 65%/82% 인데 공고당 0.46 → 2.8원 (`app/prompts/README.md`)

## 기준선을 이식할 때 지킨 것

- 원본을 **그대로** 옮겼다. `app/baseline.py` 도크스트링에 어디서 읽었는지 적어 뒀다 (BE PR #51, 로컬 `pr-51` 브랜치). BE 저장소는 읽기만 한다
- 일부러 다르게 한 것 하나: 연도 없는 날짜(`~ 9/11`)에 원본은 실행 시점 연도를 쓴다 → 측정이 해마다 달라지므로 픽스처의 `collectedAt` 연도를 썼다. **이 차이는 기준선에 유리하다**
- 기준선에는 전처리가 없다(보일러플레이트·연락처 마스킹·주입 문단 제거). 그것까지 포함해서 기준선이다 — 실제로 BE 는 `rawContent` 를 그대로 넣는다
