개인정보가 포함되는 기능(코멘트·초안)을 국내에서 처리하려면 선택지는 **HyperCLOVA X** 뿐이었다. 따라서:

## 2. 4.4.3 — 순서가 거꾸로다 (가장 중요한 정정)

**바꿀 문장**: 「LLM 으로 1차 추출하고 정규식으로 보조 검증한다」

**고쳐 쓸 내용**

반대다. **규칙이 1차, LLM 이 폴백**이다. 그렇게 만든 이유도, 그 결과도 숫자가 있다.

| 항목 | 누가 하나 | 왜 |
| --- | --- | --- |
| 마감일 | **규칙** | 범위의 끝·N차 접수·+18개월 상한·등록일 메타줄 제외 — 규칙으로 100%, 날조 0 |
| 공고 여부 판정 | **규칙** | 학사공지를 거른다. LLM 은 「공고처럼 생긴 글」을 전부 공고로 본다 |
| 유형 분류 | **규칙** 1차 → LLM 폴백 | 규칙이 100%. 애매한 것만 모델에 묻는다 |
| 지원서 문항 | **규칙** 1차 → LLM 폴백 | 줄 시작 + 번호 + 요청형 어미. 뭉친 텍스트만 모델 |
| 자격(학년·학점·전공) | **규칙** | 자격 절 안에서만 찾는다 → 100%, 날조 0 |
| **키워드 의미 선별** | **LLM** | 규칙으로는 0%. 모델이 유일하게 값을 더하는 자리 |
| 우대 조건 | 규칙(헤딩) 1차 → LLM | 헤딩이 없으면 모델 |

**이 설계의 근거**: 같은 픽스처로 세 파이프라인을 돌린 결과(4.4.7 참조), 모델이 더하는 것은 **키워드와 우대뿐**이고 나머지는 규칙이 더 정확하며 0원이다. 「LLM 1차」로 가면 비용은 늘고 정확도는 떨어진다.

## 3. 4.4.4 · 4.4.5 — 임베딩은 구현에 없다

**바꿀 문장**: 「Titan 임베딩으로 공고-사용자 벡터 유사도를 계산하고 pgvector 로 검색한다」

**고쳐 쓸 내용**

적합도 산출은 **BE 가 가져갔고**(계약 v0.2 §0), 구현은 임베딩이 아니라 **문자열 부분일치**다. 분야 유사도 40% 축이 「키워드 ↔ 관심분야 양방향 substring」이다. 보고서는 설계를 그대로 두고 **「구현은 부분일치이며 임베딩은 후속 과제」**로 명시하는 편이 정직하다.

**AI 쪽에 생기는 영향과 대응**(이건 우리 몫이라 적어 둔다): 부분일치는 과대매칭을 만든다 — 「경험」·「설계」 같은 흔한 낱말이 우대 조건 충족으로 잡힌다. 그 근거가 `/v1/comments` 로 그대로 오면 사용자는 **해 본 적 없는 일**을 자기 강점으로 읽는다. 그래서 코멘트에 **단정 방어**를 넣었다 — 근거가 낱말 하나뿐인데 「설계 능력이 있습니다」라고 쓰면 그 항목을 버린다(4.4.6).

`required`(필수 여부) 필드는 계약에 없다. 넣으려면 BE·FE 와 같이 정해야 한다.

## 4. 신설 4.4.0 — 전처리

보고서 파이프라인에는 이 단계가 아예 없다. 실제로는 **여기가 파싱 품질과 토큰 비용에 모델 선택보다 크게 영향을 준다.**

```
수집 텍스트 → 정규화(제어문자·전각공백) → 재분절(줄이 없으면 줄을 세운다)
            → 보일러플레이트 제거(이전글/목록/조회수/등록일 메타줄)
            → 주입 의심 문단 제거 → 연락처 마스킹 → 40,000자 절단
```

- **재분절이 필요한 이유**: BE 크롤러가 Jsoup `body().text()` 로 보내서 본문이 **한 줄**로 온다. 줄 전제 규칙이 전부 무너졌다가(17→15) 재분절로 복구했다(17/17)
- **마스킹**: 공고에 담당자 이메일·전화가 그대로 있다. 외부 모델에 보내기 전에 지운다
- **왜 LLM 으로 안 하나**: 전부 결정적이고 0원이며, 모델에 맡기면 매번 달라진다

## 5. 신설 4.4.6 — 가드레일

**모델 출력을 그대로 믿지 않는다.** 전부 규칙이다 — LLM 으로 LLM 을 검증하지 않는다(그 이유는 아래 「시도했다 안 쓴 것」).

| 엔드포인트 | 검증 | 통과 못 하면 |
| --- | --- | --- |
| 파싱 | 지시문 문단 제거 · 마감일 +18개월 상한 · 민감정보 문항 제거 · **차별 요구 제거** · 키워드 3개 미만/40자 초과 · JSON 스키마 1회 재요청 | `200 + parsingFailed`(+ `reasonCode`) |
| 코멘트 | **문장 단위** 근거 지목 · 사실 검증 · **단정 방어** · 차별·유해 표현 · PII 스크럽 | `null` (점수는 정상으로 나간다) |
| 초안 | 사실 검증(수치·영문 + 자격·수상·소속) · 글자 수 실측 · **문체 어미 실측** · 유해 표현 · PII 스크럽 | 재요청 → 문장 제거 → **안전 초안**(입력 문자열만으로) |
| 공통 | **전체 시한 16초** | 재요청을 포기하고 지금 답으로 끝낸다 |

**설계 원칙 셋**

1. **부탁 → 실측 → 1회 재요청.** 프롬프트로 부탁한 것을 믿지 않고 생성물에서 직접 잰다. 글자 수가 그랬고 문체가 그랬다 — 「~해요체로 써 달라」고만 하면 14건 중 2건만 지켰는데, 어미 비율을 재서 미달이면 다시 요청하니 13건이 됐다
2. **실패는 조용한 오답이 아니라 명시적 기권으로.** 못 읽은 마감일은 `null`, 근거 없는 코멘트는 `null`, 검증 못 통과한 초안은 안전 초안 + `fallback: true`
3. **차단보다 좁은 확실함.** 한국어 날조를 전부 잡으려 하면 답 하나당 30건이 걸린다(측정함). 자격·수상·소속 세 범주로 좁히니 오탐 0

**주입 방어 실측**: 공고 본문(문단 주입·인라인 주입), 경험 요약, 코멘트 근거 — 세 자리 모두 막혔다. 제일브레이크 네 수법(페르소나 전환·시스템 프롬프트 탈취·출력 형식 탈취·Base64 인코딩 우회)도 전부 막혔고, 악성 지시가 담긴 경험 카드는 **인용조차 되지 않았다**(`usedIndexes` 가 전부 `[0]`).

**한계 — 보고서에 같이 적을 것**: 주입·제일브레이크는 **종류마다 표본 1건**이다. 「막는다」가 아니라 「이 일곱 가지는 막는다」가 지금 말할 수 있는 전부다. 그리고 규칙이 못 잡는 날조가 두 종 남아 있다 — 영문의 한글 표기(「타입스크립트」)와 공고 키워드를 경험처럼 쓰는 것(「웹 접근성을 고려한 디자인을 추가했어요」).

## 6. 신설 4.4.7 — 평가·품질 측정

**이 절이 보고서에서 가장 할 말이 많은 자리다.** 「AI 담당이 무엇을 했나」에 대한 답이기도 하다.

### 6.1 무엇과 비교했나

BE 에는 AI 서버가 없을 때 쓰는 **휴리스틱 폴백**이 있고, 그 클래스 주석이 이렇게 적혀 있다 — *「품질은 LLM 구현(CareerCompass-AI)이 대체하는 것을 전제로 한 기준선이다.」* 그 자바 코드를 파이썬으로 이식해(`app/baseline.py`) **같은 픽스처·같은 채점기**로 돌렸다.

### 6.2 결과 (공고 42건 · 정답 키워드 216 · 우대 70 · 자격 111필드)

| | BE 기준선 | 우리 규칙 | **규칙 + LLM** |
| --- | --- | --- | --- |
| 마감일 | 33% | **100%** | **100%** |
| 유형 | 85% | **100%** | **100%** |
| 공고 판별 | 89%(오인 4) | **100%** | **100%** |
| 문항 개수 | 83% | 92% | **97%** |
| 자격(학년·학점·전공) | 89%(날조 3) | **100%** | **100%**(날조 0) |
| 키워드 재현 / 정밀 | 55%±7 / **41%±5** | 0% / — | 52%±7 / **68%±7** |
| 키워드 금지어 | **21** | 0 | **5** |
| 우대 재현 / 정밀 | 19% / 40% | 11% / 100% | **53% / 81%** |
| 비용 | 0원 | 0원 | 공고당 0.41원 |

### 6.3 정직하게 읽는 법 (발표에서 먼저 말할 것)

- **키워드 재현율은 기준선과 같다**(55 vs 52, 신뢰구간 안에서 겹친다). 우리가 이긴 것은 ① 규칙이 하는 것(마감일 33→100, 판별 89→100) ② **잡음 제거**(정밀 41→68, 금지어 21→5)다. BE 의 분야 유사도가 키워드 부분일치라 잡음은 점수를 직접 흐린다
- **표본 42건이라 5%p 안쪽 차이는 잡음이다.** 신뢰구간을 같이 보고해야 한다
- **자격 100% 는 과적합이다** — 같은 42건으로 규칙을 고치고 같은 42건으로 쟀다. 방어선은 회귀 테스트 8개

### 6.4 정답이 없는 기능은 어떻게 쟀나

초안·코멘트는 정답이 없다. 그래서 **어겨서는 안 되는 것**을 센다(전부 문자열 규칙, LLM 채점 없음).

| | 초안 18건 | 코멘트 12건 |
| --- | --- | --- |
| 지표 | 글자 수 준수·채움·금지 문자열·어미 일관성·톤 간 사실 일치·재생성 겹침·강조 카드 | 기대 충족·금지 문자열·미검증 토큰·문장별 근거 지목·형식 |
| 결과 | 상한 100% · 톤 구별 17/18 · 재생성 3-gram 0.25(바닥선 0.03)·문장 복사 0 · 강조 5/5 · 미검증 0 | 12/12 · 금지 0 · 미검증 0 · 근거 지목 100% |

### 6.5 시도했다 안 쓴 것 (실패도 결과다)

- **LLM 검증자(judge)**: 규칙이 못 잡는 한국어 날조를 LLM 으로 잡아 보려 했다. 붙이기 전에 쟀더니 — HCX-005 + 느슨한 프롬프트는 재현율 83%에 **오탐 61%**, 조이면 오탐 6%에 **재현율 50%**, 싼 모델(DASH-002)은 재현율 17%로 사실상 침묵. **차단용으로 쓸 수 없다**고 결론
- **한국어 날조 전수 탐지**: 「입력에 없는 한글 토큰」을 전부 플래그하면 답 하나당 30건. 문서빈도로 걸러도 10건. 범주를 자격·수상·소속으로 좁혀서야 오탐 0
- **HCX-005 로 모델 격상**: 파싱 품질은 모든 지표에서 앞서지만(키워드 59/72) 공고당 0.41 → 2.8원이고, 초안에서는 **길이를 채우려 일화를 지어낸다**
- **길이 하한 재요청**: 효과 0, 비용 1.5배

## 7. 보고서에 넣을 그림 두 장

**(1) 파이프라인** — 보고서 그림에 빠진 단계가 ①⑤⑥이다.

```
수집 → [① 전처리] → [② 규칙 추출] → [③ LLM(키워드·우대)] → [④ 병합: 규칙 우선]
                                                              → [⑤ 가드레일] → 응답
                                              ↑ 리플레이 캐시           ↓ [⑥ 평가셋·회귀]
```

**(2) 기준선 대비 막대그래프** — 6.2 표의 다섯 지표(마감일·유형·판별·문항·자격)를 기준선/우리 두 막대로. 키워드는 **재현율이 아니라 정밀도·금지어**로 그려야 메시지가 맞다.

## 8. 쓰지 말아야 할 표현

- 「**정확도 100%**」 — 반드시 「42건 기준, 신뢰구간 ±N」을 붙인다
- 「**주입을 막는다**」 — 「이 일곱 종류는 막았다(각 1건)」
- 「**AI 가 사실을 검증한다**」 — 문자열 대조 규칙이다. 한국어 날조 두 종은 못 잡는다
- 「**임베딩 기반 적합도**」 — 구현에 없다
- 「**BE 가 잘못 만들었다**」 — 「설계는 임베딩인데 구현은 부분일치다. 평가셋으로 측정했고 판단은 팀이 한다」
